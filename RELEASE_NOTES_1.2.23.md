# TG Monitor 1.2.23

Исправлено зависание всей программы на большом архиве. Когда докачанный файл заменял
прежний, программа проверяла, не нужен ли прежний файл другому сообщению, запросом
без индекса по всей базе, прямо в основном потоке. На архиве в 10 ГБ после
перезапуска такая проверка шла около 10 минут, и всё это время не работали ни
панель, ни приём сообщений. Теперь проверяются только записи этого же сообщения по
первичному ключу: имя сохранённого файла содержит номер своего сообщения. Если имя
старого формата, прежний файл просто остаётся на диске.

Панель, приём новых сообщений и загрузка истории запускаются сразу. Проверки медиа
по всему архиву (перенос папок, прерванные и пропавшие файлы, служебный чат)
выполняются в фоне: база при этом только читается, изменения вносятся точечно через
общую очередь записи. Загрузка вложений начинается после этих проверок. Раньше
запуск на большом архиве держал панель недоступной больше часа.

Фоновая загрузка больше не останавливается из-за чужой нагрузки на процессор:
история приостанавливается при загрузке всего компьютера от 90% и продолжается при
80% (было 60% и 55%); число потоков истории растёт, пока загрузка ниже 70%. Приём
новых сообщений эти ограничения по-прежнему не затрагивают. Программа при запуске
возвращает себе обычный приоритет процессора, диска и памяти: задача Windows,
которая запускает её на сервере, по умолчанию давала низкий приоритет диска, и при
занятом диске каждая запись в базу ждала в конце очереди.

Состояние фоновых проверок видно в `/api/health` (`startup_maintenance`).

Схема базы не меняется. Сообщения, сессии, медиа и настройки не затрагиваются.

Установщик сервера принимает 1.2.22, в том числе зависшую. Перед заменой он
проверяет наличие резервной копии, сделанной при установке 1.2.22, сохраняет
настройки, сессии и задачу автозапуска, и сверяет счётчики сообщений по аккаунтам
до и после запуска. Полная копия базы заново не создаётся, поэтому перерыв в работе —
несколько минут.

Проверки: 216 тестов Python и 20 тестов JavaScript на Windows/Python 3.14, в том
числе запуск с медленной проверкой медиа, приём сообщений во время неё и
остановка программы посреди проверки.
