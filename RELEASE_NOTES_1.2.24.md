# TG Monitor 1.2.24

Одинаковые вложения хранятся на диске один раз. Если один и тот же файл есть в
нескольких сообщениях — например, одно фото переслано в два чата или общий чат виден
нескольким аккаунтам, — вторая и следующие копии становятся жёсткими ссылками NTFS на
те же данные. У каждого сообщения остаётся свой путь к файлу, панель открывает и
скачивает файлы как раньше, а место на диске занимает одна копия. Удаление файла
одного сообщения не затрагивает остальные.

Одинаковыми считаются только файлы, совпадающие байт в байт (SHA-256), и проверка
повторяется непосредственно перед заменой копии ссылкой: файл, изменившийся после
подсчёта, не заменяется. Недокачанные и временные файлы не объединяются. Продолжение
недокачанной загрузки никогда не дописывает данные в файл, на который есть другие
ссылки.

Уже скачанные копии объединяются в фоне после стартовых проверок медиа: сначала
файлы наибольшего размера. Новый файл, который в Telegram уже был сохранён (тот же
идентификатор файла и размер), не скачивается повторно — сразу ставится ссылка, для
этого не нужно свободное место. Если идентификатор другой, но содержимое после
загрузки совпало с уже сохранённым файлом, копия также заменяется ссылкой.

База сообщений `monitor.db` не меняется: контрольные суммы и соответствие файлов
Telegram хранятся в отдельном файле `media-index.db` в папке данных. Его удаление
ничего не ломает — суммы будут посчитаны заново. Ход объединения и освобождённый объём
видны в `/api/health` (`media_dedupe`); объём медиа в панели учитывает общие данные
один раз.

Проверки: 222 теста Python и 20 тестов JavaScript на Windows/Python 3.14, в том числе
объединение существующих копий, отказ заменять изменившийся файл, повторное
использование файла без загрузки, объединение по содержимому после загрузки и
сохранение сообщения при сбое индекса медиа.
