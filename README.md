# TG Monitor

Полный проект с исходниками, интерфейсом, тестами и лицензиями передан в `tg-monitor-open-source.zip`. Скачайте и распакуйте архив: рабочая структура находится внутри папки `tg-monitor`. Зависимости и запуск описаны ниже и в deploy.md; результаты проверки независимого запуска — в TRANSFER_CHECK.md.

Открытый исходный код под **MIT**. Можно изменять и распространять приложение с сохранением LICENSE. Исходники: Python + обычные HTML/CSS/JavaScript, без обязательных npm, Node.js и облачной среды разработки. Лицензии включённых сторонних компонентов — THIRD_PARTY_NOTICES.md и third_party_licenses. Руководство по изменению и сборке — CONTRIBUTING.md.

## Готовое приложение для Windows

Персональная готовая версия: распакуйте **TGMonitor-Ready.zip** и откройте **TG Monitor.exe**. Распаковывайте всю папку, включая `_internal`. Python и библиотеки входят в сборку. Требуется Windows x64, доступ к Telegram и папка с правом записи.

Окна ручного ввода API ID и API hash нет. Приложение автоматически создаёт локальные настройки и открывает панель. Подключение аккаунтов выполняется в панели через QR-код или номер телефона; пароль двухэтапной защиты вводится, если он включён у аккаунта. При повторном запуске сохранённые настройки используются без замены.

Персональная сборка содержит настройки приложения в `_internal/app-defaults.ini`. Она хранится отдельно от публичного архива исходников. Универсальная сборка TGMonitor-Windows-x64.zip и исходники не содержат этих настроек: разработчик должен заранее подготовить config.ini или собственные app-defaults.ini. Форма ввода ключей отсутствует во всех вариантах; неподготовленная сборка сообщает об отсутствии настройки.

В окне приложения остаются кнопки открытия панели, папки данных и остановки. Закрытие браузера не останавливает запись; «Остановить и закрыть» останавливает сервер. Данные сохраняются в папке data рядом с приложением.

Для существующего архива разработки используйте `TG Monitor.bat` в исходной папке. Он запускает сборку с данными из этой папки. Готовая ZIP-сборка создаёт собственную чистую базу и не содержит подключённых аккаунтов, сессий или переписок. Персональная версия содержит только настройки приложения для первого запуска.

## Данные и перенос

Локальные резервные базы собраны в `backups/db`, последняя ZIP-сборка для отката — в `backups/releases`. Они не входят в распространяемые архивы. В `dist` находятся актуальная универсальная сборка, персональная готовая сборка и их ZIP, а также ZIP чистых исходников.

В `data` хранятся `config.ini`, `monitor.db`, временные WAL/SHM-файлы базы, `media`, `sessions` и журналы. Медиа связаны с сообщениями через относительные пути. Перенести свою установку можно копированием папки приложения и `data` вместе **после остановки**. Для новой установки с другой базой переносите только чистую сборку; она сама создаст новую базу. Не используйте один архив одновременно в двух процессах/на двух серверах. SQLite находится на локальном диске, не в сетевой папке.

Дополнительные настройки находятся в `data/config.ini`: `server.port`, `server.host`, `security.panel_password`. При их изменении остановите приложение. По умолчанию адрес — http://127.0.0.1:8090, доступ только с этого компьютера. Если порт занят другой программой, задайте другой порт. Пароль панели можно добавить перед запуском; API-ключи и сессии остаются локальными секретами. Лимит автоматического скачивания — 1 ГиБ; большие файлы ждут подтверждения в разделе «Файлы».

### Приём сообщений и нагрузка

Версия 1.2: догрузка использует отдельную контрольную точку истории, которую живые сообщения не сдвигают. При первом обновлении старой базы история сверяется повторно. Обработчики подключаются до соединения с Telegram; пропущенные обновления запрашиваются при подключении. Дополнительно сверяются последние 100 сообщений каждого завершённого чата для восстановления недавних правок. Неудавшаяся догрузка отображается как частичная и автоматически повторяется через минуту, пока аккаунт активен.

Ручное удаление вложения сохраняет запрет его повторной загрузки, включая догрузку истории. Скачанный файл публикуется только после проверки актуальности задания; старая загрузка не удаляет файл действующей записи. Равные временные метки правок различаются порядком приёма. Повреждённые квитанции сохраняются отдельно в `pending-ingest/quarantine` и не задерживают остальные. Единая блокировка каталога данных предотвращает запуск второго сервера с тем же архивом, включая запуск без окна.

Текст новых и изменённых сообщений сохраняется до скачивания вложений. Запись идёт вне основного цикла обработки, небольшими пакетами (до 100 сообщений); очередь приёма ограничена 256 заданиями. Вложения и недостающие профили обрабатываются тремя фоновыми задачами. Задания находятся в таблице `archive_jobs` и переживают перезапуск; неудачные попытки повторяются с увеличением интервала до пяти минут, ограничения ожидания Telegram учитываются отдельно. Карточка аккаунта показывает оставшиеся задания и повторы.

Если SQLite временно недоступна, сообщения сохраняются как локальные JSON-квитанции в `pending-ingest` и автоматически переносятся в базу после восстановления. Эту папку также включайте в перенос и резервную копию архива. Она содержит текст переписки. Нельзя гарантировать запись при одновременно недоступных базе и диске; ошибка отображается на карточке аккаунта. При штатной остановке уже принятые задания дописываются, частичные вложения остаются доступными для повторной попытки.

Короткие испытания на временной базе проверяют 50 условных аккаунтов, 1000 сообщений одновременно, восстановление после ошибки SQL и независимость приёма текста от медленной загрузки. Это не гарантия работы 50 реальных аккаунтов с любым потоком файлов: скорость зависит от диска, сети, объёма истории и ограничений Telegram. Не запускайте несколько экземпляров с одним архивом. Система продолжает работать на SQLite без дополнительных серверов и сервисов.

## Сервер и исходники

Для Windows Server запуск без окна: `"TG Monitor.exe" --headless --data-dir "D:\TGArchive"`. Сначала настройте эту папку запуском `"TG Monitor.exe" --data-dir "D:\TGArchive"`. Задача Windows или служба должна запускать EXE под постоянным пользователем с правами записи. Подробности — в deploy.md.

Для разработки: создайте Python-окружение, установите `requirements.lock`, запускайте `python app.py` с config.ini рядом с исходниками либо `python launcher.py` (с отдельной папкой data). `start_monitor.bat` остаётся вариантом запуска исходников с первоначальной установкой Python и пакетов. Для сборки установите `requirements-build.txt`, затем выполните `powershell -NoProfile -ExecutionPolicy Bypass -File .\build_portable.ps1`. Сборщик копирует только разрешённые исходники и статику, создаёт EXE и ZIP в dist. Старые результаты не перезаписываются; переименуйте предыдущую папку сборки перед новым запуском.

Проверки: `python -m unittest discover -s tests`; `python verify_bundle.py "dist\TGMonitor-Windows-x64"`. Результаты и границы проверки описаны в AUDIT.md. Приложение не подписано цифровой подписью: в Windows при первом запуске может появиться запрос доверия к издателю.

При отдельной среде сборки можно передать `-BuildPython .\.build-venv\Scripts\python.exe` в build_portable.ps1. Сборщик проверяет работоспособность Tcl/Tk перед созданием EXE.

Для публикации исходников используйте чистый tg-monitor-open-source.zip. Он содержит код, тесты, настройки-пример и лицензии; собственная база, Telegram-сессии и ключи в него не входят.
