# TG Monitor

Локальный архив Telegram с веб-панелью: несколько аккаунтов, личные и групповые чаты, переписки с ботами, поиск сообщений, вложения и управляемая очистка. Подключение аккаунта — по QR-коду или номеру телефона.

## Запуск готовой версии

Распакуйте **TGMonitor-Ready.zip** целиком и откройте **TG Monitor.exe**. Панель откроется в браузере. Python и библиотеки включены в комплект; нужны Windows x64, доступ к Telegram и право записи в папку приложения.

Персональная версия содержит настройки приложения для первого запуска и не запрашивает API ID/API hash. Аккаунты подключаются в панели; пароль двухэтапной защиты нужен только если он включён в Telegram. Закрытие браузера не останавливает запись. Для остановки используйте кнопку в окне приложения.

Универсальная сборка **TGMonitor-Windows-x64.zip** и исходники не содержат ключей. При первом запуске откроется окно настройки: укажите API ID и API hash приложения Telegram. Настройки сохраняются в `data/config.ini`; при следующих запусках сразу открывается панель. Персональную сборку с `app-defaults.ini` не публикуйте как чистые исходники.

## Данные

В каталоге данных находятся `monitor.db`, `sessions`, `media`, `config.ini` и журналы. По умолчанию это `data` рядом с приложением. Для переноса остановите программу и скопируйте приложение вместе с каталогом данных. Медиа используют относительные пути; архив не привязан к имени пользователя или папке разработчика.

Панель по умолчанию доступна только локально на порту 8090. Адрес, порт и пароль панели настраиваются в `config.ini`. Для удалённого доступа и запуска на сервере см. [развёртывание](docs/deploy.md).

Тексты сохраняются до скачивания вложений. Незавершённые документы продолжаются с сохранённого места. Очередь выбирает до 100 самых ранних готовых заданий аккаунта и отдаёт предпочтение новым попыткам и небольшим файлам внутри этой порции; аккаунты обслуживаются по очереди. Для фотографий размер проверяется по выбранной версии изображения, JPEG дополнительно декодируется перед публикацией; действительно повреждённый файл остаётся неполным. Синтетические проверки охватывают 20, 30 и 50 аккаунтов; длительная работа с таким числом реальных Telegram-аккаунтов требует отдельной проверки. Подробности и ограничения — в [отчёте аудита](docs/AUDIT.md).

## Структура исходников


Загрузка истории идёт по одному аккаунту, адаптивными порциями по 25–100 сообщений с короткими
паузами между порциями. Запись выполняет отдельный поток с постоянным соединением SQLite; режим надёжной фиксации FULL сохранён. Нативный cryptg ускоряет расшифровку Telegram. Приём новых сообщений и очередь вложений продолжаются
независимо. Сообщения и отметка прогресса фиксируются одной транзакцией; после
перезапуска загрузка продолжается с сохранённой страницы. Первый полный проход
истории не повторяется вторым полным проходом. Подготовка папок чата выбирает
только его вложения и не обходит весь каталог медиа.

```text
app.py                  API, Telegram, SQLite и архивирование
launcher.py             запуск и остановка приложения
frontend/               HTML, CSS и JavaScript панели
scripts/                сборка, проверка пакета и инструменты сопровождения
tests/                  проверки на временных данных
docs/                   разработка, развёртывание, аудит и лицензии компонентов
third_party_licenses/    оригинальные тексты сторонних лицензий
TGMonitor.spec          состав Windows-сборки
requirements.lock       точные версии библиотек
config.example.ini      пример конфигурации без секретов
```

`dist`, окружения Python, резервные копии, журналы и рабочие данные — локальные файлы, исключённые из чистого пакета. Результаты проверок хранятся в `audit-artifacts`, прежние — в `audit-artifacts/history`.

## Разработка и сборка

Для быстрого запуска исходников используйте `start_monitor.bat`. Он устанавливает окружение и открывает графическое окно для ввода ключей Telegram. Установка библиотек при первом запуске отображается в консоли; ключи в консоли не запрашиваются. Ручная настройка и команды сборки описаны в [руководстве разработчика](docs/CONTRIBUTING.md).

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
node --test tests/test_frontend.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_portable.ps1 -SourceOnly
.\.venv\Scripts\python.exe scripts/verify_bundle.py dist/TGMonitor-Windows-x64
```

Node.js нужен только для тестов JavaScript. Для работы панели npm и сборка фронтенда не нужны. `TG Monitor.bat` в рабочей папке разработчика запускает готовый EXE с существующими данными этой папки.

## Изменения 1.2.17

Запись новых сообщений и истории получает приоритет перед фоновыми операциями.
Фоновым задачам гарантированы регулярные слоты, чтобы вложения продолжали сохраняться.
Очистка осиротевших заданий использует индексные переходы по аккаунтам и удаляет
не более 100 записей за проход вместо сканирования всей очереди каждые пять секунд.
Транзакции, FULL sync, контрольные точки истории, база, сессии и медиа сохраняются.
Интерфейс и схема базы не меняются.


# TG Monitor 1.2.18

Кнопка «Догрузить незавершённое» продолжает только сохранённую очередь незавершённой
истории. Она не запрашивает список всех чатов и не перепроверяет завершённые чаты.
Очередь сохраняется при перезапуске, а автоматический повтор после ошибки использует
тот же ограниченный набор заданий. Новая первичная загрузка после прерывания
продолжается с последнего сохранённого пакета без повторного прохода старых страниц.
Для незавершённой истории старых версий сохраняется консервативная проверка глубины
только затронутого чата, чтобы не пропустить сообщения.

Изменение базы — добавление таблицы очереди; существующие записи и файлы сохраняются.
Вложения и профили продолжают обрабатываться своей очередью с прежними задержками
повтора и ограничениями Telegram. Кнопка не сбрасывает FloodWait.

Проверки: 159 тестов Python и 16 тестов JavaScript в рабочем дереве. Дополнительная
проверка чистого пакета и Windows-сборки выполняется перед публикацией.


# TG Monitor 1.2.19

Новые сообщения сохраняются пакетами в одной транзакции с контрольной точкой и
заданиями для файлов. Свежие файлы получают приоритет перед старой историей;
история сохраняет свою долю загрузки. Одновременно работают не больше трёх
загрузчиков и не больше двух для одного аккаунта.

Удалены повторные обходы файлов при неизменном аккаунте и на каждом чате истории.
Названия папок рассчитываются повторно только при добавлении, удалении или
переименовании чата; изменения отслеживаются транзакциями базы.
Проверка отсутствующего файла теперь восстанавливает только этот файл, не сбрасывая
историю всего чата. Панель читает счётчики, обновляемые в транзакциях записи,
вместо постоянного пересчёта миллионов сообщений и заданий.

Карточки показывают число сохранённых сообщений и понятные статусы загрузки,
очереди, паузы и ограничений Telegram. Кнопка «Продолжить загрузку» продолжает
незавершённую историю и пробуждает загрузчики файлов, затем сразу обновляет статус.
Завершённые чаты не перечитываются этой кнопкой. Ограничения и задержки повторов
не сбрасываются. База, история, сессии, файлы и ограничения согласования сохраняются.


# TG Monitor 1.2.20

Загрузка истории распределяется небольшими страницами между аккаунтами.
Одновременно запрашиваются не больше двух страниц. Ожидание ограничения Telegram
у одного аккаунта не занимает очередь истории остальных. Контрольные точки
сохраняются вместе с сообщениями, без сброса старого архива.

Фоновая загрузка ориентируется на общий CPU компьютера: цель55%, при60% новые
операции приостанавливаются до55%. Контроль действует и между порциями больших
файлов. Приём новых сообщений продолжается. Это адаптивное регулирование, а не
жёсткий предел ОС: другие программы и уже выполняющиеся операции могут давать пики.
Если системный счётчик недоступен, используется осторожный ограниченный темп.

Стартовая пачка истории100сообщений. Её уменьшает медленная транзакция, а не
ожидание записи за другими аккаунтами, чтобы не увеличивать число коммитов.
База, сессии, файлы, согласование больших вложений и задержки повторов сохраняются.

## Прогресс истории

Шкалы в карточках и над списком показывают сохранённые сообщения и остаток. До определения объёма проценты не показываются. Оценка отмечена ≈, так как история Telegram может меняться. 100% относится к сообщениям; файлы сохраняются отдельно.
