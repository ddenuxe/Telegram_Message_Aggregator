# TG Monitor 1.2.13 — снижение нагрузки при загрузке истории

При догрузке истории синхронные записи метаданных SQLite задерживали обработку
остальных задач. Первая загрузка также читала всю историю дважды, а подготовка
каждого чата выбирала вложения всего аккаунта и сканировала всё дерево медиа.

Теперь записи статуса рекордера, событий и прогресса истории выполняются вне
основного цикла через сериализованный writer. Порция сообщений и её прогресс
фиксируются одной транзакцией. Первая полная загрузка проходит историю один раз;
после прерывания сохранённые страницы не теряются. Догрузка работает по одному
аккаунту, порциями по 25 сообщений с паузой 50 ms; живой приём и вложения работают
независимо. Подготовка медиа ограничивает SQL нужным чатом и убирает пустые
папки только после фактического переноса, без общего обхода дерева.

Проверено: 129 Python-тестов, 13 JavaScript-тестов и smoke-тест Windows EXE
с отдельной временной базой, переносом в папку с кириллицей, отказом второго
экземпляра и штатной остановкой. Шесть новых регрессий включают реальную
конкуренцию SQLite writers, атомарный откат и продолжение после сохранённой страницы.
На одинаковой синтетической истории из 61 сообщения: 2 прохода/8 транзакций
в 1.2.12 против 1 прохода/4 транзакций в 1.2.13. Воспроизведённая задержка loop
при занятой базе снизилась с ~506 ms до ~33 ms. Это локальные измерения;
устранение всех причин торможения Windows ими не доказано.

Публичные пакеты проверены на отсутствие рабочих данных и сохранённых секретов.
Windows ZIP передаётся восемью частями `TGMonitor-Windows-x64.zip.part01`–`part08`;
`update_server_1_2_13.ps1` проверяет части и собирает исходный протестированный ZIP.
SHA256 полного ZIP: `13E59305DAF3BE3639793324255D3FF55C89540F3C198EA8DC313594D12C0897`.

Установщик рассчитан на существующую установку 1.2.12. До переключения версии
делает защищённую копию базы, конфигурации и сессий, проверяет копию SQLite.
После запуска проверяет версию, целостность и сохранность счётчиков архива.
Каталог данных и медиа остаются прежними. Схема и SQLite synchronous не меняются;
при ошибке откатывается программа, база автоматически не заменяется старой копией.

Выпуск не исправляет отдельную ошибку авторизации Telegram-аккаунта.
