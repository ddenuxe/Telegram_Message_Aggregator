# TG Monitor 1.2.14 — очередь большого архива

При большой очереди вложений выбор каждого задания сортировал всю очередь
и удерживал общий writer, задерживая сохранение истории. Теперь выбор читает
по индексу максимум 100 готовых кандидатов аккаунта и блокирует только другие
claims. Аккаунты чередуются; приоритет небольших файлов и новых попыток
действует внутри порции. Повторы, токены редактирования и атомарные checkpoint
сохранены. Счётчики очереди используют покрывающий индекс; задания уже известного
профиля не запрашивают повторно исходные сообщения в Telegram. Логи различают
таймауты Telegram и SQLite, медленные записи показывают ожидание и выполнение.

Проверено: 134 Python-теста, 13 JavaScript-тестов, Windows EXE smoke с временными
данными, переносом, защитой от второго экземпляра и штатной остановкой.
На одной синтетической базе 400000 сообщений/заданий медиана выбора задания
584.99 → 2.77 ms, списка аккаунтов 284.86 → 46.02 ms. После добавления индексов
и повторного запуска миграции все 400000 сообщений и заданий сохранены,
SQLite quick_check=ok. Это локальные измерения, не обещание такого же ускорения
сервера и не исправление отдельной нагрузки Windows Explorer.

Установщик update_server_1_2_14.ps1 предназначен для существующей установки
1.2.13: скачивает восемь частей Windows ZIP с GitHub, проверяет SHA256 частей
и целого пакета, сохраняет базу/конфиг/сессии перед переключением. Медиа остаются
в прежнем каталоге. После запуска проверяет целостность, счётчики и новые индексы.
Первый запуск строит индексы существующей базы и может занять больше времени.
При отказе переключается на прежний EXE, не заменяя базу старой копией.
